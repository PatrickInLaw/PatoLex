## 4. KEY FINDINGS / LESSONS (the trees + leaves — internalize these; several are counterintuitive)
1. **The recurring "~20k missing" is a DENOMINATOR ARTIFACT, not missing data.** California even-year sessions are tiny **Budget/Extra** sessions bound inside the adjacent ODD-year volume under an `NNchapters` label suffix (e.g. 1956's statutes live in `production-1957-vol1-56chapters`). Tools that key off the label's leading 4 digits mis-stamp them with the odd-year Regular N (~1900-2400) → false ~0% completeness. **Always measure with `chapter_vs_oracle.py`** (it decodes the suffix), never a fresh year-keyed tool. Saved to project memory.
2. **`consensus_text` is NOT an independent OCR witness** — it's the token-majority of surya/doctr/tess. Never let it vote in cross-engine agreement (it manufactures false "2-engine agreement" and inherits garbles).
3. **A 0-duplicate self-check does NOT prove correctness.** A false-positive header can emit a *unique, in-range, wrong-LOCATION* number that passes every dup gate. (This is how "Civil IX." and the 15 multi-slot off-by-ones slipped past self-checks.) For any OCR-garble-tolerant detector, require the real-act body witness COLOCATED with the header.
4. **READ THE VOLUME ITSELF, not filenames/oracle/spot-checks.** The single biggest process failure this session: I flip-flopped 3× on whether 1887's oracle (51) was right, trusting a flaky web index and filename guesses — until I finally read `production-1887`'s own front matter (page 2: "STATUTES OF CALIFORNIA, 1887 … twenty-seventh session"; index runs to ch ~185). The answer was in the volume's printed index/cover the whole time. **The printed TOC/index is the authoritative internal source for chapter count + chapter→page map.**
5. **page ≠ chapter.** Don't estimate re-OCR page counts from chapter counts; a page can hold several short acts and an act spans pages. Use the index's Page column.
6. **The oracle (`ca_chapter_counts.tsv`) is UNRELIABLE in places** — it was seeded from a clerk web index that undercounts (it shows "Statutes 1–51" for 1887, a ~185-chapter session). **Hans-confirmed real undercounts: 1887 (51→~188) and 1883-84 (23→~96)** — both gaps too large for noise, oracle implausibly low for the era. 1863 (476→538) plausible, spot-check. **NOT real: 1865-66 (index said 650) — a parser artifact, prior 280 stands.** 1858/1891 (+2) = noise. **So our 92.7% has an error bar (mostly in the early era 1858–1903), and in genuinely-undercounted sessions we actually HOLD real chapters the too-low N was capping out of the count.**
7. **Verify "missing/unparsed/wrong" against SOURCE + OCR content before claiming it.** ~7 false "missing data" alarms this campaign all dissolved into present-or-recoverable data.

## 5. THE CURRENT CRITICAL PATH: index re-derivation (oracle reconciliation)
- `rederive_index_counts.py` parses each volume's printed index, compares to oracle, **overwrites nothing** (Patrick's instruction: "second, more authoritative signal — compare, don't overwrite").
- **Result so far: only 19/222 volumes parsed** — MATCH 12, ORACLE_LOW 6 (undercounts: 1865-66 280→650⚠, 1887 51→188, 1883-84 23→96, 1863 476→538, 1858 358→360, 1891 280→282/modal-year-1872⚠), ORACLE_HIGH 1 (1880-code 126→121), **NO_INDEX 203.**
- **How robust:** the parser does NOT take a raw max (which one garbled token would inflate). It takes the **top of the contiguous-from-1 run** of index chapter numbers, trims isolated OCR outliers, and applies a **coverage gate (≥0.75 distinct/max)** + **truncation guard** — demoting any garbled/sparse index to NO_INDEX rather than emitting a wrong count. Session is confirmed from the ordinal phrase + modal approval-year (title-page year ignored — OCR-garbled). It also auto-remaps label→oracle where needed (1900-01 → 1901 Regular = 275 MATCH; 1881 → Extra = 103 MATCH).
- **Controls validate it:** 1885-86 169=169 MATCH, 1889 290=290 MATCH, 1895/1897/1899/1903 MATCH, 1859/1863-64/1867-68/1880 MATCH — and 1887 correctly flagged 51→188. It reproduces the oracle wherever the oracle is known-right.
- **CRITICAL STRUCTURAL FINDING — the 203 NO_INDEX is mostly NOT a parser weakness:** **every volume from ~1905 forward is NO_INDEX because the modern multi-volume OCR bundles BEGIN at the statute body (`CHAPTER 1.`) — the printed CONTENTS/index pages are NOT inside these bundles at all.** So you cannot index-re-derive the modern era from the current data; you would need to OCR the printed CONTENTS pages separately (they exist in the source scans / chief-clerk-archive PDFs but were never bundled). The early-era roman volumes parsed partially (`cov=0.5–0.8`) and could be improved, but the modern gap is an **acquisition/OCR-scope** issue, not a regex fix.
- **Good news / scoping:** the oracle errors found are **concentrated in the early era (1858–1903), exactly where the index parser works** — so the re-derivation has already surfaced the worst denominator errors (1887, 1883, 1865-66, 1863). The modern-era oracle mostly MATCHes in the controls, so its denominator is less in doubt (its main known issue is the even-year bundling artifact, §4.1, a measurement-labeling fix not an oracle error). **#1 next task: (a) reconcile/flag the early-era oracle errors found; (b) decide whether to OCR the modern CONTENTS pages for a full cross-check; (c) re-measure.**
- **HANS VERDICT on `rederive_index_counts.py` (done 2026-06-17):** Script is **WRITE-SAFE** (read-only on oracle + parses; new files only) and **NO_INDEX handling is functionally correct** (no NO_INDEX is silently treated as MATCH/0). BUT the count logic has flaws → trust the discrepancies in tiers:
