# Lessons Overview

Index of lessons learned during the PatoLex project.

## Inherited Lessons (from Pato template, 2026-04-27)

These lessons came from the template's own setup history and apply to any new repo using this template:

- **Don't hardcode model versions in tooling.** Co-author attribution should be `Claude Code <ClaudeCode@Kolasinski-Law.com>` -- survives model upgrades without churn.
- **`block-compound-bash.ps1` is non-negotiable.** Compound bash (`&&`, `||`, `;`, `cd ...`) causes endless permission prompts. Hook included by default in this template; do not disable.
- **Verbose session-log naming wins.** `SESSION_ccNNN_SUMMARY_YYYY-MM-DD_Title.md` browses much better in Explorer than `ccNNN-summary.md`.
- **Bump enforcement must tolerate missing VersionInfo.cs.** Pre-scaffold mode is built into `bump.ps1` and the pre-bash hook; do not remove the file-existence checks.
- **Parallelize template-porting and other mechanical work.** Repo setup is mostly content adaptation of known files. Batch by directory and dispatch parallel Sonnet/Haiku subagents -- don't sequence Opus through it. Estimated savings: ~3/4 wall-clock time, ~1/2 tokens.
- **Codex window title should be project-specific.** This repo uses `PatoLex_Codex`.
- **Hooks: omit `"shell": "powershell"` in settings.json.** Setting this causes `$CLAUDE_PROJECT_DIR` to be evaluated as a PowerShell variable (empty), breaking the path. Let Claude Code do the substitution by leaving the field out.

## PatoLex-Specific Lessons (cc001)

- **Supabase port rule (applies to the future Supabase serving deployment, not the current build DB):** use port 6543 (PgBouncer) for Vercel serverless functions; port 5432 (direct) for any long-running pipeline process. Serverless functions exhaust the 60-connection limit on the direct URL. **Currently (2026-06-09): the active DB is local PostgreSQL 16 at `localhost:5432/patolex` — Supabase is a planned future serving deployment only.**
- **`service_role` key must never appear in client-side code.** Use `anon` key for browser-facing calls; `service_role` only in Next.js Server Components / Route Handlers / tRPC procedures running server-side.
- **Read the template FIRST, then build.** On cc001, the agent started building before fully reviewing the sample repo and had to stop and restart. Cost: extra time and context. Rule: always extract and read the full template before touching the new repo.
- **Write tool requires Read first.** Claude Code's Write tool will refuse to overwrite a file it hasn't read this session. On large repo setups, batch-read target files before batch-writing, or accept the read-then-write sequence for each file.

- **[LESSON_2026-06-20_ocr_header_garble_dedup.md](LESSON_2026-06-20_ocr_header_garble_dedup.md)** — OCR `CHAPTER`-header garble is the SHARED root cause of both apparent "missing" chapters (header didn't OCR cleanly: "UHAPTER 9", "CHAPTER 2338"=238) and phantom-duplicate chapters (a bodyless stub under a garbled number on another chapter's page). The safe same-act dedup in `merge_passes.py` **fuzzy-anchors** on the word CHAPTER (≤2 edits, digit-cleaned, capped at oracle N) so garbled-header chapters are protected, and collapses a same-page pair ONLY on **body** near-identity (Jaccard ≥0.6) or a **bodyless STUB** with a matching title — **never** on title-similarity alone (boilerplate appropriation titles → deletes real chapters; killed real ch6 San Quentin in testing). Header-anchored acts are never dropped; weak signals are flagged, not deleted. 1900–1999 honest completeness **95.2%**; 267 dups collapsed, 1024 flagged across 178 vols. Extends [LESSON_2026-06-14](LESSON_2026-06-14_chapter_recovery_header_loss_and_renumber.md).

- **[LESSON_2026-06-22_residual_manifest_crossvolume_anchor_collapse.md](LESSON_2026-06-22_residual_manifest_crossvolume_anchor_collapse.md)** — When a session-year is split across **two physical volumes sharing the same chapter-number range** (main Statutes + separately-paginated `*-code` Amendments vol), `_residual_manifest.py` **collapses both into one chapter→page map**, so any missing chapter bracketed by one-neighbor-from-each-volume gets a **garbage `page_range`** (1876: 17 items, spans to **820 pp**, e.g. ch467 lo_pg751 main / hi_pg39 code — different PDFs). The 1874 dual-WINDOW guard does NOT fix this (it scans the wrong volume's region). **FIX: re-derive anchors from the MAIN volume's present chapters only (drop overlap chapters) and scan the bounded sequential window (cap ~40 pp) between nearest main-vol neighbors.** Converted 820-pp bogus spans → tight 8–15 pp windows; recovered the formerly-mis-anchored cluster (419,468,469,496,512,519) while leaving true misses residual. CONFIRM-ONLY, 0 spurious entries. 1876 residual 138→59 (+79). Detect `*-code` siblings (see `YEAR_DIR_ALIAS`: 1874/1876/1878) before any header-OCR pass. - **[LESSON_2026-06-23_vlm_recovery_ops_dpi_thrash.md](LESSON_2026-06-23_vlm_recovery_ops_dpi_thrash.md)** — Operational findings from re-running Qwen2.5-VL over the 71 human-review chapters (lifted 29→47 recovered, 71→24 remain). (1) Single-process VLM loops THRASH on a full card — killed runs may not free VRAM (verify nvidia-smi, kill stray python; clean baseline ~889 MiB), and 350 dpi fills the 32 GB card. Thrash signature = util 100% but POWER collapses (~127 W vs ~350 W). Fix: clean card + 250 dpi + `torch.cuda.empty_cache()` per page → ~365 W, ~3-4 s/page (was ~156 s/page). (2) **250 dpi read BETTER than 350** (over-large images get downsampled lossy inside the vision encoder → blurs small text) — higher DPI ≠ better recall. (3) Typo-reconciliation false-positive: only treat read-number N as a typo of target c if N is OUT of its own sequence slot (occupying c's), not when N is a present chapter at its correct page (1872 ch126 vs real ch124). (4) "TRUE-GAP" is wrong for interior chapters — consecutive numbering means they exist; a continuous-sequence read = under-listed short act, not absence. Pagination verified ACCURATE (offset +0, median 1.0 pages/chapter). Builds on [LESSON_2026-06-23_scrivener_roman_transposition](LESSON_2026-06-23_scrivener_roman_transposition.md).
- **[LESSON_2026-06-23_scrivener_roman_transposition.md](LESSON_2026-06-23_scrivener_roman_transposition.md)** — Printed session-law volumes occasionally have a SOURCE scrivener typo in a chapter's Roman numeral (adjacent-letter swap, e.g. `CXLIII`=143 mis-set as `CLXIII`=163). When OCR reads the typo faithfully the act is filed under the WRONG chapter — hiding the real chapter (false "missing") AND masking a genuine gap (the typo'd number's slot looks satisfied). Verified instance: **1869-70 ch.143** (at pdf p210, stored as 163; the real ch.163 sits unparsed at p291–292). Targeted adjacent-swap scan (`_scrivener_scan2.py`) found **exactly 1 corpus-wide** → rare, no campaign needed; the more common typo→OCR-fail variant lands in the residual and is caught by HUMAN REVIEW (which is how this was found). Correction (relabel 163→143 + recover real 163) deferred to the corrections / citation re-derivation prereq (ROADMAP §25 items 5 & 8). Don't trust a residual *count* to reflect residual *identity* in a typo'd volume. Relates to [LESSON_2026-06-21](LESSON_2026-06-21_early_era_roman_cccc_additive.md).
- **[LESSON_2026-06-23_glob_vs_alias_three_tools.md](LESSON_2026-06-23_glob_vs_alias_three_tools.md)** — The greedy `production-<year>*` dir-resolution glob sweeps in the WRONG sibling volume (`production-1907-09`=1909 not 1907; `production-1953-vol1-52chapters`=1952-budget not 1953-regular) unless it excludes `BUDGET_OWNED_DIRS` and defers to `pipeline/year_dir_alias.py`. Also decoupled `BIENNIAL_YEARS` from `PDF_FOR_YEAR.keys()` so new single-series years use the legacy page-finder not the dual-series sequence-finder. - **[LESSON_2026-06-22_external_acquisition_scan_gaps.md](LESSON_2026-06-22_external_acquisition_scan_gaps.md)** — Acquiring an EXTERNAL copy to fill a physical scan gap (a missing printed leaf that re-OCR can't recover). **The trap:** the CA Assembly Chief Clerk online archive (`clerk.assembly.ca.gov/.../archive/Statutes/<yr>/<vol>.pdf`) IS the source of our local scans — re-downloading it re-acquires the **same** missing leaf (verified: 1927 v.1 + 1986 v.3 downloads were byte-equivalent — identical page counts 2399/1947 and identical printed-page gaps). **Always compare page-count + OCR the gap region against the local copy before trusting a "new" source.** **What works:** Google Books full-volume PD download (`books.google.com/books/download/x.pdf?id=<GBID>&output=pdf`, browser UA, no login) — recovered **1905 ch389-397 (residual 9→0)** from the CDL/UCD copy (GBID `mKlAAQAAMAAJ`). **What's walled:** HathiTrust full-vol PDF + single-page image both 403 (member login only); only its Bib API is open (`catalog.hathitrust.org/api/volumes/full/recordnumber/<rec>.json`). **Coverage negative:** the open digitized bound-Statutes serial covers only thru 1967 (+stray 1972) — 1927/1929/1970/1981/1985/1986 have no gap-free free scan, leaving 6 of 7 volumes UNOBTAINED. Authoritative index = CDL "California Legislative Publications" Google Sheet (Statutes tab **gid=0**; address tabs by gid, gviz `sheet=name` silently mis-falls-back). - **[LESSON_2026-06-21_scan_gap_vs_header_loss_visual_recovery.md](LESSON_2026-06-21_scan_gap_vs_header_loss_visual_recovery.md)** — A residual-missing chapter has **three** distinguishable causes; only the first two are software-fixable: (a) page-top header-loss (body present), (b) OCR consensus/engine error (mine all 4 engines, not just `consensus_text` — e.g. 1970 ch1013: docTR+Surya read "1013", Tesseract misread "1015", consensus wrongly chose Tesseract), and (c) **physical scan gap — a printed leaf was never digitized.** A scan gap is **invisible** at the filename level (`pages_raw` filenames stay contiguous); the ONLY tell is the **running-head printed page number jumping** across consecutive images (1970 vol1: `page_1646.png`=printed 1647 → `page_1647.png`=printed 1649, so printed leaf **1648** holding ch906/907 was never scanned). An OCR-text-only analysis mis-diagnosed it as "lostheader" because text alone can't tell the two apart. A scan gap is **NOT a legislative gap** → record `status="not_found_needs_reocr"`, `printed_number_confirmed=false`, needs re-scan. 1970 result: 6 missing → 4 `image_verified` (707,733,1013,1139), 0 legislative_gap, 2 not_found scan-gap (906,907). Image mapping for `production-*` volumes is by **source/PDF page**: `pages_raw/page_{source_page-1:04d}.png`.
- **[LESSON_2026-06-22_biennial_volume_offset_merge_cap.md](LESSON_2026-06-22_biennial_volume_offset_merge_cap.md)** — Biennium-named dirs (`production-EVEN-ODD`) are **offset by one year**: the odd-year REGULAR session is bound with the preceding even-year EXTRA session (`production-1906-07` = 1907 Regular N=539 + 1906 Extra N=64; `production-1907-09` = 1909 Regular N=729). `merge_passes.n_for()` regex-grabs the **leading even year**, whose only oracle row is the tiny extra session, so the merge caps at that N (64) and clips the real odd-year regular data (certified ch 3–539) down to ch ≤ 64 — leaving the year falsely "green" against the wrong volume and the true regular year UNMAPPED. **Same bug as 1901/09/11.** Fix: back up the wrong `merged.json`, re-run the EXISTING `merge_dir(D, N)` with the correct odd-year N (never hand-fabricate), then in `_recall_allyears.py` add the collision dir to the glob-exclusion set and alias each odd year to its biennial dir. 1907: 60→529 ch, residual 7; 1909: mapped, residual 5; unmapped list emptied; corpus incl-unmapped 98.7%→99.4%; assert PASS. **Tell-tale: a `cap_N` of 1/15/64 in a biennial dir's `_merge_meta`.** Durable fix still owed: teach `n_for()`/the merge CLI the same alias map.
- **[LESSON_2026-06-22_H5_digit_misread_not_sequence_bug.md](LESSON_2026-06-22_H5_digit_misread_not_sequence_bug.md)** — The merge dup-audit's H5 heuristic flagged 1913 & 1917 as standout "cohort" volumes with recurring **+/-5 / +/-50** heading-vs-filed offsets, smelling like a systematic per-volume **sequence cascade**. It is **NOT** — local header-OCR ground-truthed **every** high/med candidate (16 in 1913, 8 in 1917) as **filed `chapter_int` CORRECT (100%)**. The offsets are ordinary **single-digit OCR substitutions** on the body heading line (**22/24 differ by exactly one digit**; histogram dominated by **5<->0** x8 and **3<->8** x8). A "+/-50" is just a 5->0 misread in the **tens** column; "+/-5" the same in the **units** column. Decisive disproof of a cascade: the filed spine is **monotonic, dup-free, 1..N** in both volumes (a real +50 shift would collide chapter_ints). **Gotcha:** in these volumes the page-TOP running head is the **printed PAGE NUMBER**, not "CHAPTER N" — so use the **full-page multi-psm header scan + neighbor-sequence confirmation**, not the top-strip-as-arbiter rule. **No data fix (0 chapters); the defect is in the audit** — H5 should suppress flags that are a single-digit confusable-pair substitution on an in-sequence chapter. Same signature visible in 1907/1919/1921/1923.
